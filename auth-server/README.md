# Code5 Auth Server

Сервис аккаунтов для Code5 Launcher. Он хранит пользователей и сессии в PostgreSQL,
отправляет шестизначные коды через SMTP и выдаёт одноразовые билеты для входа на
Minecraft-сервер.

## Локальный запуск

```powershell
npm install
npm test
npm start
```

Без `DATABASE_URL` и SMTP сервис работает только в режиме разработки: данные
хранятся в памяти, а код возвращается тестовому клиенту. В `production` такой режим
запрещён.

## VDS с Node.js и Nginx

1. Создать DNS-запись для `AUTH_DOMAIN`, направленную на VDS.
2. Установить PostgreSQL, создать отдельную базу и пользователя `code5`.
3. Разместить содержимое этой папки в `/opt/code5-auth` и выполнить `npm ci --omit=dev`.
4. Скопировать `.env.example` в `/etc/code5-auth.env` и заменить все секреты, адрес базы и SMTP-реквизиты.
5. Создать системного пользователя `code5auth` без домашней папки.
6. Установить `deploy/code5-auth.service` в `/etc/systemd/system/` и запустить службу.
7. Заменить `AUTH_DOMAIN` в `deploy/nginx-code5-auth.conf`, подключить файл в Nginx и выпустить HTTPS-сертификат через Certbot.
8. Проверить `https://AUTH_DOMAIN/health`.

API слушает локальный порт `8787`, а наружу публикуется только через Nginx по HTTPS.
PostgreSQL также не должен быть доступен из интернета.

## VDS с Docker

Если порты 80 и 443 свободны, можно скопировать `.env.example` в `.env`, заполнить
его и выполнить `docker compose up -d --build`. В этом варианте Caddy автоматически
получает и обновляет TLS-сертификат.

Minecraft-сервер обращается к API локально по `http://127.0.0.1:8787`.

### Gmail

Для Gmail используются `smtp.gmail.com`, порт `465` и `SMTP_SECURE=true`.
В `SMTP_PASS` указывается отдельный 16-значный пароль приложения Google, а не
основной пароль аккаунта. Для создания пароля приложения должна быть включена
двухэтапная проверка.

Секрет `SERVER_API_KEY` должен совпадать со значением переменной
`CODE5_AUTH_SERVER_KEY` у Minecraft-сервера. Его нельзя добавлять в мод или
репозиторий.
